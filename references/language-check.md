# 语言自然性核查判据

> 语言自然性是四类检查里最容易产生**无效意见**的一项。
> 不给明确判据，AI 会输出一堆"建议润色""可更流畅"式的意见，浪费复核时间。
> 本文给出可判定的具体模式——**只报命中这些模式的问题，不做泛泛的文采评价。**

## 通用铁律

1. **申报资料不是文学作品**。语言问题只在下面三种情况下才值得报：
   - ① 造成**歧义**（可能被审评方理解成另一个意思）
   - ② 明显的**机翻腔/语法错误**，影响专业观感
   - ③ 与同一份文件其他地方的**表述风格不一致**
2. **不报纯风格偏好**。"这句可以更简洁"不是问题，除非它造成歧义。
3. **不改专业术语**。看起来啰嗦的规范表述（如"研究者或其授权人员"）通常是刻意的，不要建议简化。

## 一、中文资料（递交 CDE）

### 1. 欧化句式 / 机翻腔

| 模式 | 例 | 改法 |
|---|---|---|
| "被"字滥用 | 受试者**被**给予药物 | 受试者接受给药 / 给予受试者 |
| "进行/予以 + 动词" 堆叠 | 对样本**进行**检测**进行**分析 | 检测并分析样本 |
| "的"字长定语套叠 | 在筛选期**的**符合入选标准**的**受试者**的**基线数据 | 拆句 |
| "通过……得以……" | **通过**该方法**得以**实现质量控制 | 该方法可实现质量控制 |
| 主语缺失后接"其" | ……，**其**应在 24 小时内上报 | 明确"其"指谁 |
| "作为……而言" / "关于……方面" | 冗余框架词 | 直接删 |

### 2. 表意含混（**必报**，会造成执行歧义）

- **"及时/尽快/适当/必要时"**——申报资料里凡涉及时限、判定的地方出现这类词，
  必须确认是否别处已有明确定义；没有定义就是可执行性缺陷
- **"原则上"**——后面是否给了例外情形？没给就是空话
- **"等/等等"**——封闭列举后面加"等"，等于把清单变成开放的，
  与方法论第 5 条（封闭性措辞）冲突，需确认是有意还是笔误
- **"相关的/有关的"**——相关于什么？常见于从英文 relevant 直译

### 3. 中英混排

- 中文句子里的英文缩写**首次出现是否给了中文全称**（`docqc.py` 会检出未定义缩写）
- 中英文之间的空格是否全篇统一（有的加、有的不加）
- 数字与单位：`5mg` / `5 mg` / `5毫克` 是否混用
- 标点：中文句子里误用半角标点 `,` `;` `(` `)`

### 4. 称谓一致性

同一对象全篇是否统一：受试者 / 患者 / 病人 / 志愿者；
研究者 / 研究医生 / 主要研究者；申办方 / 申办者 / 委托方。
**这一条与方法论第 4 条"术语三形态"呼应，是中文资料最高发的问题。**

## 二、英文资料（递交 FDA）

### 1. Chinglish 高发模式

| 模式 | 例 | 改法 |
|---|---|---|
| 中式主题句 | *About the safety, it was evaluated by...* | *Safety was evaluated by...* |
| 冗余名词化 | *conduct an analysis of* | *analyze* |
| "will be" 滥用于既成事实 | *Subjects will be enrolled* （描述已完成的研究） | *Subjects were enrolled* |
| 冠词缺失 | *Investigator should report AE* | *The investigator should report the AE* |
| 单复数不一致 | *Each subjects* | *Each subject* |
| 悬垂修饰 | *After signing the ICF, the study drug was administered* | 主语错位，改为 *After the subject signed the ICF, ...* |

### 2. 时态一致性（**必查**）

- **Protocol**（前瞻性）：应统一用 will / is to be，不要混入过去时
- **CSR**（回顾性）：应统一用过去时，不要混入 will
- **同一份文件里时态漂移**是最常见的问题，尤其是从方案复制到 CSR 的段落

### 3. 情态动词的法规含义（**必查，影响合规**）

英文申报资料里这几个词有明确的强弱之分，不能随意互换：

| 词 | 含义 | 误用后果 |
|---|---|---|
| **must / shall** | 强制 | 把建议写成强制，自我加码 |
| **should** | 推荐 | 把强制写成推荐，可能被认为未遵循 |
| **may** | 允许 | 把强制写成允许 |
| **will** | 陈述计划 | —— |

从中文"应"翻译过来时最容易出错——中文的"应"同时可以对应 should 和 shall，
必须回到上下文判断是强制还是推荐。

### 4. 术语与拼写

- 美式 vs 英式拼写全篇是否统一（randomization / randomisation，program / programme）
- 药物名：INN 通用名 vs 商品名是否混用；首字母大小写是否统一
- 与 FDA 惯用表述对齐：*adverse event* 而非 *adverse reaction*（除非确指 ADR）

## 三、输出要求

语言类发现同样要进主问题清单，并且：

- **触发规则**列写"语言自然性"
- **严重度**：造成执行歧义的（如"及时上报"未定义时限、情态动词误用）算**中或高**；
  纯表达不地道算**低**
- 必须给**原文摘录 + 建议改法**，不能只写"建议润色"
- 低严重度的语言问题**合并成一条汇总**，不要一条一条刷屏，
  否则会淹没真正重要的一致性和逻辑问题
