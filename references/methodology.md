# 文档一致性核查方法论

> 来源：一次真实的多文档核查复盘（方案 + 2 份 ICF + 3 份 IND 模块），含双智能体独立核查后的比对复盘。
> 用途：指导文本层核查，同时作为写"核查提示词"的元规则。

---

## 一、最核心的一条

**核查失效，绝大多数不是"没查"，而是"用错了查法"。**

字符串比对只能证明"同一个词在各处写法一致"，但真正致命的是
"**用不同的词，表达了互斥的要求**"——这类问题字符串比对完全无感。

**实测数据**：一次核查中，用"关键词命中/未命中矩阵"做完 21 项跨文档比对，
全部通过、结论"可定稿"；换一种查法后，在同一批文件里查出 **10 条高优先级矛盾**，
结论变成"不可定稿"。其中 3 条是核查者自己前几轮亲手留下的。

---

## 二、三类不一致，各用各的查法

| 类型 | 表现 | 查法 | 危害 | 机器能力 |
|---|---|---|---|---|
| **表层不一致** | 同一数值/名称在各处写法不同 | 关键词矩阵比对 | 低 | 强 |
| **语义不一致** | 不同措辞表达出互斥要求 | 概念枚举 + 两两比对 | **最高** | 弱，需人判 |
| **结构不一致** | 编号、引用、合计、状态时态 | 逐条打开、重算、走查 | 中高 | 中 |

**多数团队只做了第一类。** 排查投入应该倒过来分配。

> 本 Skill 的 `docqc.py` 已覆盖第三类的大部分（编号连续性、交叉引用悬空、缩写冲突、样式统一），
> 以及第一类中格式相关的部分。**第二类只能靠人/AI 按下面的方法查。**

## 三、九条可迁移的操作规则

### 1. 先建"概念清单"，再建"数据点清单"

数据点清单是**名词**（申办方名称、例数、剂量、日期）；
概念清单是**动词与规则**——"怎么做""什么时候做""谁来决定""多长时间""什么情况下例外"。

**互斥矛盾几乎全藏在动词里。**
建议每个项目先列 8–15 个关键操作概念，对每个概念把全文所有相关句子**全部摘出来**，
再两两比对是否可同时成立。

临床试验方案的常见关键概念举例：
提前退出流程 / 提前终止标准 / 方案偏离上报时限 / 采样时间窗 / 剂量调整规则 /
知情同意撤回后的数据处理 / 揭盲条件 / 合并用药限制 / 随访失访判定 / 安全性事件上报路径

### 2. "未命中"永远不是结论，只是线索

假阴性率高得惊人。已实证的来源：文本折行、破折号变体（`--` / `–` / `—`）、
直/弯引号、上标与域代码、XML 转义（`&lt;`）、格式转换引入的标记。

**规则：机器判"缺失" → 人工回原文确认 → 才能写进报告。** 经验值约三分之一是假的。
反向也成立：报告里应单列"假阴性复核记录"，用来自证做过这一步。

### 3. 数值不只要对，还要追依赖链

一个数字会沿链条传播。核查时画链，改动时更要画链。

通用链条模板：
`单位用量 → 频次 → 单次小计 → 累计总量 → 据此推导的阈值 → 引用该阈值的入排标准 → 对外披露文件（同意书/摘要）`

链上任一环节改动，其余全部重算。
**表格的分项之和必须与所载合计逐个验算**——自称 100% 实际 88.5% 这种事真实发生过。

### 4. 术语要扫三种形态

缩写、拼写全称、同义表达。只扫缩写会漏掉全称。

**实证**：全文缩写已清零，全称仍残留两处，且其中一处就在新写内容的隔壁，
同一列表里两个称谓打架。

> `docqc.py` 会抽取"全称（缩写）"定义对并报冲突，但**同义表达查不了**，仍需人工。

### 5. 凡"全部 / 唯一 / 完整 / 汇总了所有"必须穷举验证

封闭性措辞是高危信号。
**实证**：某附录自称"汇总了全部洗脱要求"，实际漏收 5 类、又新增 4 类正文未定义的。

### 6. 凡条件性 / 例外性条款必须走场景

构造具体情形跑一遍，检验是否可执行。

通用必走场景：提前退出、提前终止、中断后恢复、周末与节假日、
极值人群（最低体重/最高年龄）、某中心不具备某条件。

**实证**：一条"参照末次给药的等效 24 小时时点采样"的规定，
在提前停药场景下时间点落在过去，物理上无法执行。

### 7. 凡法定措辞必须回查法条，不得照抄模板

模板里的 "as required by law" 未必适用于你的研究。
**实证**：1 期研究套用了只适用于 "applicable clinical trial" 的强制告知语。

### 8. 凡可实测的断言必须实际执行

能渲染、能计算、能打开的就去做，不要凭源码推断。
**实证**：曾据缓存值判定"转 PDF 会显示错误页码"，实测后完全不成立——该字段渲染时会重算。

> 这条正是本 Skill 强制"必须运行 `docqc.py`"的原因。

### 9. "没提到"不等于"一致"

先判断该文件是否**本应**涉及该项。结论必须三分：**一致 / 不一致 / 不适用**。
把沉默记成一致，是虚假安全感的主要来源。

## 四、改文件本身也要 QC（最容易被忽略）

核查者动手修改时引入的新错误，与原有错误同样常见。已实证的四类：

1. **批量替换过度命中**——把某个交叉引用全局替换，连带改坏了另一处本来正确的同名引用。
   **禁止无差别全局替换交叉引用，必须逐处确认指向对象。**
2. **删段留空壳**——整段删除后留下空段落，带列表样式的会渲染成空的项目符号。
   结构性编辑后必须扫：空段、空表行、悬空标题、孤儿脚注、失效引用、目录脱节。
3. **插错位置**——说明句插进了目录（因为目录条目与正文标题同名，取了第一个匹配）；
   新增采样点插在了错误的顺序位置。
   **定位标题时注意目录与正文同名，一般应取最后一个匹配。**
4. **克隆继承错误格式**——以标题段为模板克隆出的"正文"变成了加粗标题样式。

**规则：每次修改后做全文逐字符差异比对，确认"只动了预期位置"，并检查标点是否留下悬空逗号。**

## 五、双通道核查：投入产出比最高的一招

两个独立执行者用**同一份提示词**核查**同一批文件**，重叠度可能极低——
因为方法偏好不同，各自的盲区也不同。

**实测**：两份报告合并去重后共 30 条发现，其中**两边都查出来的只有 1 条**，
其余 29 条都是只有一方发现、另一方完全漏掉的。
即：**单独跑一轮，会漏掉另一轮能找到的绝大部分问题**——
这不是说那些发现不成立，而是说"只核查一轮"这件事本身不可靠。

原因是双方方法偏好不同、盲区也就不同：
一方强于数值复算与格式对称性，另一方强于语义矛盾与递交完整性；一方误报 0 条，另一方误报 2 条。

**结论：安排两轮独立核查再合并去重，效果远好于同一人做两遍。**
合并时必须逐条回原文验证对方的发现——本次验证出 2 条不成立
（一条误读上标为章节号，一条未实测就下结论）。

## 六、写"核查提示词"的元规则

1. **写"怎么查"而不是"查什么"**——只给数据点清单，执行者会退化成字符串比对
2. **每条方法绑一个真实反例**——让执行者知道违反的后果长什么样，比抽象要求有效得多
3. **加约束句**："违反任何一条强制方法，该条发现不予采信。"
4. **加提交前自检清单**——逐条打勾，不通过不提交
5. **输出表格里加"触发规则"一列**——记录每条发现是靠哪种方法抓到的。
   跑几轮之后就能看出哪类方法产出最高，据此调整下一版提示词

## 七、报告应自带可验证性

好的核查报告要让二次审阅者能**低成本推翻你**：

- 每条发现给**两处原文**：本处摘录 + 与之冲突的另一处摘录
- 每个数字给**算式**：算式 + 计算结果 + 文档所载值 + 是否相符
- 每条"缺失"给**复核记录**
- 严重度分三级，并写明**分级依据**（是否影响科学有效性 / 受试者安全 / 法规合规）
- 单列**不适用清单**，与"一致清单"分开

做不到这几点的报告，下一个人只能全部重做。
