# 核查提示词模板

> **用法**：复制下面的基线提示词，替换 `[方括号]` 里的项目信息，
> 分别粘贴进**两个互不共享历史的新会话**里各跑一遍，再人工合并两份结果。
>
> **为什么必须跑两遍**：实测两份独立报告合并去重后共 30 条发现，
> 其中两边都查出来的只有 1 条，其余 29 条都是只有一方发现、另一方漏掉的。
> 也就是说，单独跑一轮会漏掉另一轮能找到的绝大部分问题。

## 如何让两轮的互补性最大化

实测中两轮的强项自然分化了：**一方强于数值复算与格式对称性，
另一方强于语义矛盾与递交完整性。** 与其指望这种分化偶然发生，
不如**刻意分工**——在两轮都跑完整基线的前提下，各追加一个不同的侧重镜头。

- **两轮都跑完整基线**：保证独立复核的价值，
  且任何一项不会因为"没分给谁"而两边都漏
- **各加一个镜头**：把偶然的互补变成必然的互补

具体做法：先粘贴下面的【基线提示词】，再在末尾追加【通道 A】或【通道 B】的镜头段。

| | 追加镜头 | 侧重 |
|---|---|---|
| **通道 A** | 数值与结构镜头 | 数值依赖链、表格验算、编号与引用、格式对称性、跨文件数值一致 |
| **通道 B** | 语义与执行镜头 | 互斥要求、条件场景可执行性、封闭措辞穷举、术语三形态、递交完整性 |

> 材料特别重要时可加跑第三轮，用通道 A 的镜头但换一个新会话，
> 用来验证 A 轮的数值类发现是否可复现。

## 【基线提示词】（两个通道都要跑）

```
你是一名独立的文档一致性核查员，不参与本文件的起草，只挑问题，不要为已有写法辩护。

【核查对象】
文件清单：[列出全部待核查文件，并标注哪一份是唯一事实来源]
递交去向：[CDE / FDA]
资料语种：[中文 / 英文]

【第零步：格式层必须先跑工具，不许靠读】
你读到的是纯文本，不带字体、字号、行距、页边距信息。禁止凭阅读给出任何格式结论。
先执行：
    python3 ~/.codex/skills/clinical-doc-qc/scripts/docqc.py check [文件...] --profile [cde|fda]
把工具输出作为格式层与结构层的事实依据，再继续下面的文本层核查。

【第一步：先建概念清单，不要直接开始比对】
先自行通读全文，列出 8–15 个关键操作概念（动词/规则，例如"怎么做、什么时候做、
谁决定、多长时间、什么情况例外"，不是人数/剂量这类数据点）。
覆盖范围由文档实际内容决定。

下面是我已经想到的几项，请并入你的清单并优先处理；
但这只是补充，不是核查范围的全部——你自行枚举出的其他概念同样要查：
[按项目补充，例如：提前退出流程 / 方案偏离上报时限 / 采样时间窗 /
剂量调整规则 / 知情同意撤回后的数据处理]

对每个概念，把全文相关句子全部摘出来，两两比对是否可能同时成立——
这一步是核查的核心，不是可选项。

【第二步：三类不一致分开查，重点在第②类】
①表层不一致：同一数值/名称在各处写法是否一致（日期格式、缩写、单位）。
②语义不一致（权重最高）：不同措辞是否表达出互斥的要求，仅字面一致不代表通过。
③结构不一致：编号、交叉引用、合计数、时态与状态标注是否前后一致。
（③的大部分工具已覆盖，重点核对工具报出的项并补充工具查不了的部分）

【第三步：数值依赖链】
凡涉及计算/推导的数字，画出依赖链，逐环核对；
表格分项之和必须与所载合计逐个验算。
通用链条：单位用量→频次→单次小计→累计总量→据此推导的阈值→引用该阈值的入排标准→对外披露文件
本项目的数值链条：[按项目实际数值关系补充]

【第四步：高危措辞专项复核】
出现"全部/唯一/完整/汇总了所有"等封闭性措辞的地方，逐条穷举验证是否真的完整。
条件性/例外性条款，代入具体场景实际走一遍，确认物理上可执行：
提前退出、提前终止、中断后恢复、周末与节假日、极值人群、某中心不具备某条件。
涉及法定/合规措辞的地方，回查是否确实适用于本研究，不要假设模板照抄就对。
适用法规清单：[按项目/申报路径补充]

【第五步：错别字、用词与语言】
按 references/language-check.md 的判据核查，分三档：
① 错别字（必报）：同音字（的地得、须需、已己）、形近字、多字漏字、
   单位大小写（mL/mg/μg）。
② 用词错误（必报）：容易混用但含义不同的词——不良事件与不良反应、
   发生率与发病率、疗效与有效性、剂量与剂型与规格、入选与入组与筛选、
   失访与脱落与退出。英文另查 affect/effect、dose/dosage、
   efficacy/effectiveness、incidence/prevalence。
③ 语言自然性：只报造成歧义的、明显机翻腔/语法错误的、与全文风格不一致的。
   不要输出"建议润色""可更简洁"这类无判据的意见。
同一错误重复出现合并成一条并注明次数；低严重度的语言问题合并成一条汇总，
不要逐条刷屏。

【第六步（仅当任务包含直接修改文件时执行）】
修改完成后：逐处确认交叉引用指向的对象，禁止无差别全局替换；
扫一遍有没有空段落/空表行/悬空标题/失效引用；
确认没有把内容插进目录而不是正文同名标题下；
做一次全文差异比对，确认只动了预期位置。

【强制约束】
判定为"缺失/未提及"的项，一律标记为"待人工复核"，不得直接写成一致或不一致的结论。
每一项结论必须三选一：一致 / 不一致 / 不适用——先判断该文件是否本应涉及这一项，
不适用不能算作一致。
违反以上任意一条方法得出的发现，不予采信。
不要在同一轮里自我评价"整体没问题"，只输出发现清单。

【输出格式】
先给「覆盖范围声明」：列出本次实际建立的完整概念清单（8–15 项），
每项标注来源（自行枚举 / 用户点名）与结论（一致 / 不一致 / 不适用 / 待人工复核）。
任何未覆盖的范围必须在这里显式写出，不得静默省略。

再给「问题清单」表格：
序号 | 触发规则（概念清单/表层/语义/结构/数值链/封闭措辞/条件场景/语言/格式层工具）|
严重度（高/中/低，注明依据：科学有效性/受试者安全/法规合规）| 位置 |
原文摘录A | 冲突摘录B（若有）| 结论（一致/不一致/不适用/待人工复核）| 说明

【提交前自检，逐条确认才能提交】
□ 格式层是否真的运行了 docqc.py，而不是靠阅读推断
□ 是否先建了概念清单，不是直接做字符串比对
□ 概念清单是否由自己通读全文枚举得出，而不是只照抄我点名的那几项
□ 是否给出了覆盖范围声明，未覆盖的部分是否显式写出
□ 语义矛盾是否按概念两两比对过，不只是表层核对
□ 所有"未命中"是否都标了待复核，没有直接下结论
□ 所有结论是否都是一致/不一致/不适用三选一，没有用沉默代替一致
□ 涉及计算的数字是否按依赖链逐环核对，分项之和与合计是否验算过
□ 封闭性措辞是否逐条穷举验证，条件性条款是否代入场景走过
□ 输出表格是否每条都标了触发规则，是否给了两处摘录/算式/复核记录
```

## 【通道 A】数值与结构镜头（追加在基线提示词末尾）

```
【本轮额外侧重：数值与结构】
在完成上述全部基线核查的前提下，本轮再用下面这个镜头把材料过一遍。
这是叠加，不替代基线的任何一步。

1. 逐个复算：文中出现的每一个可计算的数字，自己算一遍再与文档所载值比对，
   在报告中列出算式。包括但不限于：累计剂量、暴露量、样本量、
   各组例数之和、百分比与其分子分母、随访时长、时间窗上下限。
2. 表格专项：每张表的分项之和与所载合计逐个验算；行列标题与单元格内容
   是否错位；同一指标在不同表中的取值是否一致；表内单位是否统一。
3. 编号与引用的对称性：表/图/附录编号是否连续无跳号，
   每个编号是否都被正文引用过（有编号但正文从未提及，往往是删改遗留），
   每处引用是否都指向真实存在的对象。
4. 跨文件数值一致：同一数值在方案、ICF、IB、摘要中是否完全一致，
   特别注意四舍五入位数不同导致的"看起来一样其实不一样"。
5. 时间轴自洽：所有时间点、访视窗口、时长相加是否与总周期吻合，
   有无重叠或空档。
```

## 【通道 B】语义与执行镜头（追加在基线提示词末尾）

```
【本轮额外侧重：语义与可执行性】
在完成上述全部基线核查的前提下，本轮再用下面这个镜头把材料过一遍。
这是叠加，不替代基线的任何一步。

1. 互斥要求专项：对概念清单里的每一项，明确写出"如果同时按 A 处和 B 处执行，
   会发生什么"，据此判断两处是否真的可以同时成立。
   不要只看措辞像不像，要看要求本身是否冲突。
2. 可执行性推演：挑出全部含条件、例外、时限的条款，各构造一个具体情形
   实际走一遍，确认物理上能执行。必走：提前退出、提前终止、中断后恢复、
   周末与节假日、极值人群（最低体重/最高年龄）、某中心不具备某条件、
   受试者撤回知情同意后的数据处理。
3. 封闭性措辞穷举：找出所有"全部/唯一/完整/汇总了所有/仅限于"等表述，
   逐条把它声称涵盖的内容与正文实际定义的内容做全集比对，
   报告漏收与多出的项。
4. 术语三形态：对每个关键术语，同时扫描缩写、拼写全称、同义表达三种形态，
   只扫缩写会漏掉全称（实测发生过：缩写已清零、全称仍残留两处）。
5. 递交完整性：站在审评方角度问——按本材料声称的设计，
   是否有必需但未提供的信息、未定义就使用的概念、
   前文承诺"详见后文"但后文没有的内容。
```

## 合并两轮结果时

1. 两份报告并排，**逐条回原文验证**——实测会有误报（一条误读上标为章节号，一条未实测就下结论）
2. 重合的条目合并，只保留证据更完整的那份表述
3. 只出现在一份报告里的条目**不要因为"另一份没提"就降级**——
   两边查出的问题几乎不重叠是正常现象（实测 30 条里只有 1 条是两边都发现的），
   "另一份没提"通常意味着那一份漏掉了，而不是这一条不成立
4. 合并后按严重度重排，高严重度在前
5. **给每条标注它来自哪个通道、触发规则是什么**。跑过几个项目之后统计一下：
   哪个镜头产出高、哪类触发规则命中多、哪些误报集中出现在哪一侧——
   据此调整下一版的镜头分工，而不是一直凭感觉用同一套。

### 还要留意"两边都没查到"的盲区

双通道只能覆盖两个镜头照到的地方。合并完成后，回头看一眼**覆盖范围声明**：
两份报告的概念清单是否有明显缺项？如果两边枚举出的概念高度雷同，
说明两轮可能被同一种思路带着走，此时值得再补一轮——
换一个切入角度（例如"假设我是核查员来现场检查，会先查什么"），
而不是把同样的提示词再跑第三遍。
