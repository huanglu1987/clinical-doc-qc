# 核查提示词模板

> **用法**：复制下面整段，替换 `[方括号]` 里的项目信息，
> 分别粘贴进**两个互不共享历史的新会话**里各跑一遍，再人工合并两份结果。
> **为什么必须跑两遍**：实测两份独立报告合并去重后共 30 条发现，
> 其中两边都查出来的只有 1 条，其余 29 条都是只有一方发现、另一方漏掉的。
> 也就是说，单独跑一轮会漏掉另一轮能找到的绝大部分问题。

---

```
你是一名独立的文档一致性核查员，不参与本文件的起草，只挑问题，不要为已有写法辩护。

【核查对象】
文件清单：[列出全部待核查文件，并标注哪一份是唯一事实来源]
递交去向：[CDE / FDA]
资料语种：[中文 / 英文]

【第零步：格式层必须先跑工具，不许靠读】
你读到的是纯文本，不带字体、字号、行距、页边距信息。禁止凭阅读给出任何格式结论。
先执行：
    python3 ~/.codex/skills/clinical-doc-qc/scripts/docqc.py check [文件...] --profile [cde|fda]
把工具输出作为格式层与结构层的事实依据，再继续下面的文本层核查。

【第一步：先建概念清单，不要直接开始比对】
先自行通读全文，列出 8–15 个关键操作概念（动词/规则，例如"怎么做、什么时候做、
谁决定、多长时间、什么情况例外"，不是人数/剂量这类数据点）。
覆盖范围由文档实际内容决定。

下面是我已经想到的几项，请并入你的清单并优先处理；
但这只是补充，不是核查范围的全部——你自行枚举出的其他概念同样要查：
[按项目补充，例如：提前退出流程 / 方案偏离上报时限 / 采样时间窗 /
剂量调整规则 / 知情同意撤回后的数据处理]

对每个概念，把全文相关句子全部摘出来，两两比对是否可能同时成立——
这一步是核查的核心，不是可选项。

【第二步：三类不一致分开查，重点在第②类】
①表层不一致：同一数值/名称在各处写法是否一致（日期格式、缩写、单位）。
②语义不一致（权重最高）：不同措辞是否表达出互斥的要求，仅字面一致不代表通过。
③结构不一致：编号、交叉引用、合计数、时态与状态标注是否前后一致。
（③的大部分工具已覆盖，重点核对工具报出的项并补充工具查不了的部分）

【第三步：数值依赖链】
凡涉及计算/推导的数字，画出依赖链，逐环核对；
表格分项之和必须与所载合计逐个验算。
通用链条：单位用量→频次→单次小计→累计总量→据此推导的阈值→引用该阈值的入排标准→对外披露文件
本项目的数值链条：[按项目实际数值关系补充]

【第四步：高危措辞专项复核】
出现"全部/唯一/完整/汇总了所有"等封闭性措辞的地方，逐条穷举验证是否真的完整。
条件性/例外性条款，代入具体场景实际走一遍，确认物理上可执行：
提前退出、提前终止、中断后恢复、周末与节假日、极值人群、某中心不具备某条件。
涉及法定/合规措辞的地方，回查是否确实适用于本研究，不要假设模板照抄就对。
适用法规清单：[按项目/申报路径补充]

【第五步：语言自然性】
按 references/language-check.md 的判据核查。只报三类：造成歧义的、明显机翻腔/语法错误的、
与全文风格不一致的。不要输出"建议润色""可更简洁"这类无判据的意见。
低严重度的语言问题合并成一条汇总，不要逐条刷屏。

【第六步（仅当任务包含直接修改文件时执行）】
修改完成后：逐处确认交叉引用指向的对象，禁止无差别全局替换；
扫一遍有没有空段落/空表行/悬空标题/失效引用；
确认没有把内容插进目录而不是正文同名标题下；
做一次全文差异比对，确认只动了预期位置。

【强制约束】
判定为"缺失/未提及"的项，一律标记为"待人工复核"，不得直接写成一致或不一致的结论。
每一项结论必须三选一：一致 / 不一致 / 不适用——先判断该文件是否本应涉及这一项，
不适用不能算作一致。
违反以上任意一条方法得出的发现，不予采信。
不要在同一轮里自我评价"整体没问题"，只输出发现清单。

【输出格式】
先给「覆盖范围声明」：列出本次实际建立的完整概念清单（8–15 项），
每项标注来源（自行枚举 / 用户点名）与结论（一致 / 不一致 / 不适用 / 待人工复核）。
任何未覆盖的范围必须在这里显式写出，不得静默省略。

再给「问题清单」表格：
序号 | 触发规则（概念清单/表层/语义/结构/数值链/封闭措辞/条件场景/语言/格式层工具）|
严重度（高/中/低，注明依据：科学有效性/受试者安全/法规合规）| 位置 |
原文摘录A | 冲突摘录B（若有）| 结论（一致/不一致/不适用/待人工复核）| 说明

【提交前自检，逐条确认才能提交】
□ 格式层是否真的运行了 docqc.py，而不是靠阅读推断
□ 是否先建了概念清单，不是直接做字符串比对
□ 概念清单是否由自己通读全文枚举得出，而不是只照抄我点名的那几项
□ 是否给出了覆盖范围声明，未覆盖的部分是否显式写出
□ 语义矛盾是否按概念两两比对过，不只是表层核对
□ 所有"未命中"是否都标了待复核，没有直接下结论
□ 所有结论是否都是一致/不一致/不适用三选一，没有用沉默代替一致
□ 涉及计算的数字是否按依赖链逐环核对，分项之和与合计是否验算过
□ 封闭性措辞是否逐条穷举验证，条件性条款是否代入场景走过
□ 输出表格是否每条都标了触发规则，是否给了两处摘录/算式/复核记录
```

---

## 合并两轮结果时

1. 两份报告并排，**逐条回原文验证**——实测会有误报（一条误读上标为章节号，一条未实测就下结论）
2. 重合的条目合并，只保留证据更完整的那份表述
3. 只出现在一份报告里的条目**不要因为"另一份没提"就降级**——
   两边查出的问题几乎不重叠是正常现象（实测 30 条里只有 1 条是两边都发现的），
   "另一份没提"通常意味着那一份漏掉了，而不是这一条不成立
4. 合并后按严重度重排，高严重度在前
