# clinical-doc-qc · 临床试验资料核查 Skill

一个给 **Codex / Claude Code** 用的 Skill：全面核查临床试验申报资料的
**一致性、逻辑性、语言自然性、格式规范**，支持**单文件内部核查**与**多文件交叉核查**，
按 **CDE（中文）** 和 **FDA（英文）** 两套规则集分别判定格式合规性。

适用资料：临床试验方案、知情同意书（ICF）、研究者手册（IB）、临床研究报告（CSR）、
IND / NDA 各模块，以及任何需要前后一致的申报文件。

## 它解决什么问题

一次真实的核查复盘发现：

> 用"关键词命中/未命中矩阵"做完 21 项跨文档比对，**全部通过**，结论"可定稿"；
> 换一种查法后，在**同一批文件**里查出 **10 条高优先级矛盾**，结论变成"不可定稿"。
> 其中 3 条还是核查者自己前几轮亲手留下的。

**核查失效，绝大多数不是"没查"，而是"用错了查法"。**
字符串比对只能证明"同一个词写法一致"，但真正致命的是
**用不同的词表达了互斥的要求**——这类问题字符串比对完全无感。

本 Skill 把这套方法论固化下来，并补上 AI 单独做不到的格式层检查。

## 核心设计：两层分离

**这是本项目最重要的设计，也是不这么做就一定会出错的地方。**

> AI 读到的文档是纯文本，**不携带字体、字号、行距、页边距信息**。
> 让 AI"读一遍"判断排版是否合规，它只会编造结论。

所以核查被严格拆成两层：

| 层 | 查什么 | 由谁执行 |
|---|---|---|
| **格式层 + 结构层** | 字体、字号、行距、颜色、页边距、纸张；表图编号连续性、交叉引用悬空、缩写定义冲突 | `scripts/docqc.py` 解析文件 |
| **文本层** | 内容前后矛盾、逻辑自洽性、语言自然性 | AI 按 `references/methodology.md` |

工具只报告**事实**（"正文实际是宋体 12pt、左边距 2.1cm"），
规则集才做**判断**（"2.1cm < 2.5cm，违反 CDE 规定"）。
这样规则改了不用改代码，也不会出现 AI 猜字体的情况。

## 安装

### 前置要求

- Python 3.8+
- Codex CLI 或 Claude Code

### 一键安装

```bash
git clone https://github.com/huanglu1987/clinical-doc-qc.git
cd clinical-doc-qc
bash install.sh
```

`install.sh` 会做三件事：安装 Python 依赖 → 把 Skill 复制到 `~/.codex/skills/clinical-doc-qc/` → 跑一次自检。

### 手动安装

```bash
pip3 install python-docx pypdf pymupdf
mkdir -p ~/.codex/skills
cp -r clinical-doc-qc ~/.codex/skills/
```

Claude Code 用户把目标路径换成 `~/.claude/skills/`。

### 验证安装

```bash
python3 ~/.codex/skills/clinical-doc-qc/scripts/docqc.py --help
```

能看到帮助信息即安装成功。

## 怎么用

三种用法按**核查深度**区分，不按文件数量区分——
**每一种都既能查一份文件、也能一次查多份**：传一份就是单文件内部核查，
传多份会自动附带跨文件比对（字体字号是否统一、同一缩写在不同文件里有没有被定义成不同全称等）。

| 用法 | 什么时候用 | 深度 | 需要 AI |
|---|---|---|---|
| **一 · 全面深度核查** | 正式提交前、需要查逻辑与语义矛盾 | 最深：概念清单 + 数值依赖链 + 语义比对 + 格式 + 语言 | 是 |
| **二 · 格式 + 文字校对** | 定稿前快速过一遍 | 较浅：格式 + 错别字 + 用词 + 目录 + 编号引用 | 是 |
| **三 · 双通道核查** | 正式提交材料**必做** | 用法一跑两遍再合并 | 是（两个独立会话） |

只想要客观格式事实、不需要 AI 的，直接跑命令行即可（见用法二末尾）。

### 用法一：全面深度核查（最常用）

装好之后，在 Codex 对话框里用自然语言描述需求即可，不需要记命令行参数。
以下提示词可以直接复制修改使用。

#### 示例 1 · 标准版（多份资料交叉核查）

**这是完整版提示词，后面几个示例都在它的基础上追加。**
每一条都对应一种已被实测证明有效的查法，删掉任何一条都会降低检出率。

```
用 clinical-doc-qc 核查以下这套申报资料，递交去向 CDE、中文资料：
~/项目/方案_V2.0.docx
~/项目/ICF_受试者版.docx
~/项目/IB_V3.docx

【格式层】
1. 先实际运行 docqc.py，不要凭阅读判断字体、字号、行距、页边距。
   把工具报的错误/警告整理成可执行的整改说明。

【文本层：怎么查】
2. 先自行通读全文，枚举 8–15 个关键操作概念（动词与规则：怎么做、
   什么时候做、谁决定、多长时间、什么情况例外），覆盖范围由文档内容决定。
   对每个概念把全文相关句子全部摘出来，两两比对是否可能同时成立。
   不要退化成关键词/字符串比对。
3. 下面几项请并入清单并优先处理，但这只是补充、不是核查范围的全部，
   你自行枚举出的其他概念同样要查：
   入排标准、剂量与给药方案、访视安排、安全性事件上报时限、退出与终止规则
4. 数值类：画出依赖链逐环核对（单位用量→频次→单次小计→累计总量→
   据此推导的阈值→引用该阈值的入排标准→ICF/摘要等对外文件），
   表格分项之和必须与所载合计逐个验算，并在报告中给出算式。
5. 凡出现"全部/唯一/完整/汇总了所有"等封闭性措辞，逐条穷举验证是否真的完整。
6. 凡条件性/例外性条款，代入具体场景实际走一遍，确认物理上可执行：
   提前退出、提前终止、中断后恢复、周末与节假日、极值人群（最低体重/最高年龄）、
   某中心不具备某条件。
7. 文字层：错别字（同音字、形近字、漏字、单位大小写 mL/mg/μg）、
   用词错误（不良事件与不良反应、发生率与发病率、疗效与有效性、
   剂量与剂型与规格、入选与入组与筛选、失访与脱落与退出）。
   同一错误重复出现合并成一条并注明次数。

【强制约束】
8. 判定为"缺失/未提及"的项一律标记为"待人工复核"，不得直接写成结论
   （实测这类判断约三分之一是假阴性）。
9. 每项结论必须三选一：一致 / 不一致 / 不适用——先判断该文件是否本应涉及这一项，
   不能把沉默当成一致。
10. 不要在同一轮里自我评价"整体没问题"，只输出发现清单。
11. 违反以上任何一条方法得出的发现，不予采信。

【输出】
12. 先给覆盖范围声明：列出实际建立的完整概念清单，每项标注来源
    （自行枚举/我点名）与结论；任何未覆盖的范围必须显式写出。
13. 再给问题清单表格：序号 | 触发规则 | 严重度（高/中/低，注明依据：
    科学有效性/受试者安全/法规合规）| 位置 | 原文摘录A | 冲突摘录B |
    结论 | 说明。数值类给算式，语义矛盾必须给两处原文。
```

> **为什么第 3 条要写"不是范围的全部"。** 如果只写"重点核查以下五项"，
> AI 很容易把这五项当成范围上限，其余部分查得很浅。而人在列举时往往是凭印象举例、
> 不是穷举——**你能想到的风险点，恰恰是已经注意过、因而不太容易出错的部分**，
> 真正的问题常在没想到的地方。
>
> **正式提交的材料**请用 [`templates/review-prompt.md`](templates/review-prompt.md)
> 的完整模板 + 用法三的双通道，检出率明显高于单跑一轮。

#### 示例 2 · 只核查一份方案的内部一致性

把示例 1 的文件清单换成单份，并在末尾追加：

```
这是单文件内部一致性核查，重点在同一份文件内前后是否自洽：
- 同一规则在不同章节是否存在互斥表述（访视窗口、剂量调整、退出标准等）
- 同一数值在正文、表格、流程图、附录中是否一致
- 术语与缩写全篇是否统一（含全称、缩写、同义表达三种形态）
- 目录条目与正文标题是否对得上
```

#### 示例 3 · 英文资料递交 FDA

把示例 1 的"递交去向 CDE、中文资料"改为"递交去向 FDA、英文资料"，
第 7 条的文字层换成英文判据，并追加：

```
第 7 条改为英文判据：拼写错误、大小写一致性（p-value / mL / μg）、
affect 与 effect、dose 与 dosage、efficacy 与 effectiveness、
incidence 与 prevalence。

额外加强（不替代上述常规核查）：
- 时态是否统一（Protocol 应为前瞻性时态，不要混入过去时；CSR 反之）
- 情态动词 must / shall / should / may 使用是否准确
  （中文"应"翻译过来时最容易把强制写成推荐）
- 美式与英式拼写是否全篇统一
```

#### 示例 4 · 改完之后的复核

```
我按上一轮问题清单改完了这份方案：~/项目/方案_V2.1.docx
上一轮清单见附件/见下方粘贴。

请用 clinical-doc-qc 做复核，分三部分：
1. 逐条对照上一轮清单，确认每条是"已改对/未改/改了但不彻底/改错了"，
   不要只看是否动过，要看改后的表述是否真的解决了原问题。
2. 检查修改本身有没有引入新问题（这类新错误与原有错误同样常见）：
   - 交叉引用是否被批量替换改坏，逐处确认指向对象
   - 有没有删段后留下的空段落、空表行、悬空标题、失效引用
   - 新增内容是否插到了正确位置（注意目录与正文标题同名，应取正文那处）
   - 修改处的格式（字体/字号/行距）是否与全文一致
   - 改了某个数值后，依赖它的下游数值是否全部重算
3. 按示例 1 的完整流程重新核查一遍，不要因为"只改了几处"就跳过全文核查。
```

**AI 收到后会自动：**

1. 运行 `docqc.py` 拿到格式层与结构层的**事实**
2. 按方法论做文本层核查——**先建概念清单**（动词与规则），而不是直接做字符串比对
3. 追数值依赖链、穷举封闭性措辞、代入场景走条件条款
4. 按 `language-check.md` 判据核查语言自然性
5. 输出一张带 **触发规则 / 严重度 / 两处原文摘录** 的问题清单

### 用法二：格式 + 文字校对（比用法一轻，定稿前过一遍）

用法一是**深度核查**（建概念清单、追数值链、查逻辑矛盾），耗时较长。
如果只想在定稿前快速过一遍**格式与文字**，用这个模式。

它同样需要 AI 参与——因为错别字、用词错误、目录内容是否对得上，工具判不了。

#### 示例提示词

```
用 clinical-doc-qc 对这份资料做「格式 + 文字校对」，递交去向 CDE：
~/项目/方案_V2.0.docx

这次只做格式与文字校对，不做深度逻辑核查，覆盖以下几类：
1. 格式合规：先实际运行 docqc.py，不要凭阅读判断字体字号。
   把工具报的错误/警告整理成可执行的整改说明。
   工具会一并查出修订痕迹与批注残留、域代码错误、页眉页脚不一致、
   日期格式混用、半角标点、括号不配对、空段落、文档属性等。
   其中"残留修订痕迹/残留批注/域代码错误"请单独置顶列出——
   它们会被接收方直接看到，且递交后无法追回。
2. 错别字：同音字（的地得、须需、已己）、形近字、多字漏字、
   单位大小写（mL/mg/μg）。
3. 用词错误：容易混用且含义不同的词——
   不良事件与不良反应、发生率与发病率、疗效与有效性、
   剂量与剂型与规格、入选与入组与筛选、失访与脱落与退出。
4. 目录与正文：目录条目和正文标题是否对得上、有无遗漏或多余条目。
5. 其他：编号是否连续、交叉引用是否指向存在的对象、
   缩写首次出现是否定义、图表标题措辞风格是否统一。

要求：
- 同一个错误重复出现时合并成一条并注明次数，不要逐处刷屏。
- 每条给出所在位置与原文摘录，便于我直接定位修改。
- 不确定是不是错的（例如疑似专有名词、疑似有意为之的格式），
  单独列为"待确认"，不要直接判成错误。
- 报告开头写明"本次为格式+文字校对，未做深度逻辑与一致性核查"，
  让我清楚哪些没查。
```

英文资料把最后的去向换成 FDA，第 3 条换成：
`拼写错误、大小写一致性（p-value / mL / μg）、affect与effect、dose与dosage、efficacy与effectiveness`

#### ⚠ 关于目录页码：.docx 查不了，必须用 PDF

这是个容易踩的坑：**.docx 里目录的页码是「域」的缓存值**，
Word 打开或转 PDF 时会重新计算。在未渲染状态下读到的数字可能早已过期，
**据此判定"页码错误"会得出与事实相反的结论。**

所以工具的行为是：

| 格式 | 目录标题比对 | 目录页码比对 |
|---|---|---|
| `.docx` | ✅ 查（目录有而正文无 / 正文有而目录无） | ❌ 不判，只提示转 PDF 后复核 |
| `.pdf` | ✅ 查 | ✅ **真正比对**（页码已渲染，是实的） |

正确做法：**在 Word 里右键目录 → 更新域 → 更新整个目录 → 导出 PDF → 对 PDF 再跑一次。**

PDF 侧的页码比对还做了防误报处理：正文页码与 PDF 物理页序常有固定偏移
（封面、扉页占位），工具按**众数偏移**判定，只报偏离整体的条目，
不会因为"整体差 1 页"就把每一条都报成错。

### 用法三：双通道核查（正式提交必做）

**先解释这一步为什么必要。**

一次真实实验：让两个互不知情的执行者，用**同一份提示词**核查**同一批文件**，各出一份报告。
两份报告合并去重后共 **30 条**发现，其中**两边都查出来的只有 1 条**，
剩下 29 条都是只有一方发现、另一方完全漏掉的。

> 换句话说：**任何单独跑一轮的核查，都漏掉了另一轮能找到的绝大部分问题。**
> 不是说那 29 条有问题，而是说"只跑一轮"这件事本身不可靠。

原因是两边的方法偏好不同、盲区也就不同——
一方强于数值复算与格式对称性，另一方强于语义矛盾与递交完整性。

所以正式提交的材料，**不要只跑一轮**：

1. 打开 [`templates/review-prompt.md`](templates/review-prompt.md)，
   把【基线提示词】里的 `[方括号]` 换成本项目信息
2. 在**两个互不共享历史的新会话**里各粘一遍（**不是同一个会话里跑两次**——
   同一会话第二次会受第一次结论影响，等于没有第二个独立视角）
3. **给两轮各追加一个不同的镜头**（见下）
4. 人工合并两份结果，**逐条回原文验证**再采信
   （实测两份报告里也各有误报：一条把上标误读成章节号，一条没实测就下了结论）

#### 让两轮互补最大化：刻意分工

实测中两轮的强项自然分化了——一方强于数值复算与格式对称性，
另一方强于语义矛盾与递交完整性。与其指望这种分化偶然发生，不如**刻意分配**：

| | 追加镜头 | 侧重 |
|---|---|---|
| **通道 A** | 数值与结构 | 逐个复算、表格验算、编号引用对称性、跨文件数值一致、时间轴自洽 |
| **通道 B** | 语义与执行 | 互斥要求推演、条件场景可执行性、封闭措辞穷举、术语三形态、递交完整性 |

**两轮都要跑完整基线**，镜头是叠加在基线之上的——
这样既保留独立复核的价值（同一处被两边各查一次），
又让两边的额外投入落在不同地方。镜头段的完整文本见模板文件。

> 这一步 Skill 强制不了，必须人工执行。但它是所有招数里投入产出比最高的一个：
> 多花一轮的时间，换回来的是差不多翻倍的问题检出率。

> **合并完还要回头看一眼覆盖范围声明**：如果两份报告枚举出的概念高度雷同，
> 说明两轮可能被同一种思路带着走，此时补第三轮应该**换一个切入角度**
> （例如"假设我是核查员来现场检查，会先查什么"），而不是把同样的提示词再跑一遍。

### 命令速查

工具本身只有三个子命令，都支持一次传多个文件：

| 命令 | 作用 |
|---|---|
| `check <文件...> --profile cde\|fda` | **最常用**。按规则集判定；传多份时自动附带跨文件比对 |
| `compare <文件...>` | 只输出跨文件差异，不输出每份文件各自的问题。<br>适合"格式已经各自查过了，只想看几份之间统不统一"的场景 |
| `extract <文件...>` | 只输出格式事实（字体、字号、页边距、目录条目…），不做任何判定。<br>加 `--json` 可接入其他流程 |

```bash
# 一次核查三份，含跨文件比对
python3 ~/.codex/skills/clinical-doc-qc/scripts/docqc.py check 方案.docx ICF.docx IB.docx --profile cde

# 只看这三份之间统不统一
python3 ~/.codex/skills/clinical-doc-qc/scripts/docqc.py compare 方案.docx ICF.docx IB.docx
```

跨文件能查出：字体/字号/页边距不统一、
**同一缩写在不同文件里被定义成不同全称**（多文档最高发的一致性问题）。

## 能查出什么

### 格式层（工具自动判定）

| 检查项 | CDE | FDA |
|---|---|---|
| 中文字体 | ✅ 宋体 | — |
| 西文字体 | ✅ Times New Roman | ✅ Times New Roman / Arial |
| 正文字号 | ✅ 小四（12pt） | ✅ 12pt |
| 表格字号 | ✅ ≥五号（10.5pt） | ✅ ≥10pt |
| 行距 | ✅ 1.5 倍 | — |
| 字体颜色 | ✅ 黑色 | — |
| 纸张 | ✅ A4 | — |
| 页边距 | ✅ 分纵/横向判定 | ✅ ≥1 英寸 |
| PDF 版本 / 加密 / JavaScript | — | ✅ |
| PDF 书签 / 字体嵌入 / 可搜索 | ✅（部分） | ✅ |
| 文件大小 ≤200MB | ✅ | — |

### 结构层（工具自动判定，CDE / FDA 通用）

- ✅ **表 / 图 / 附录编号是否连续、有无重复**（如"表编号从 1 到 3，中间缺 2"）
- ✅ **交叉引用是否悬空**（正文写"详见表 5"，但全文根本没有表 5）
- ✅ **同一缩写被定义成不同全称**（AE 一处是"不良事件"、另一处是"不良反应"）
- ✅ **高频使用但从未定义的缩写**
- ✅ 标题层级跳级（H1 直接跳 H3）
- ✅ 同一样式内部字体/字号不统一
- ✅ 页边距在文档内不统一
- ✅ **目录条目与正文标题是否对得上**（目录有而正文无 / 正文有而目录无）
- ✅ **目录页码是否正确**（仅 PDF，见下方说明）

### 定稿前校对项（工具自动判定，`.docx`）

这一组的共同点是**会被接收方直接看到、且递交后无法追回**，
所以优先级高于其余格式问题：

| 检查项 | 级别 | 说明 |
|---|---|---|
| **残留修订痕迹** | ✗ 错误 | 未接受的插入/删除/移动/格式修订，接收方会看到全部修改历史 |
| **残留批注** | ✗ 错误 | 内部讨论的批注忘了删 |
| **域代码错误** | ✗ 错误 | "错误！未找到引用源"这类文本会直接印在纸面上 |
| 页眉页脚不一致 | ⚠ 警告 | 各节页眉不同——改版本号/方案编号时常漏改其中一处 |
| 日期格式混用 | ⚠ 警告 | `2026-01-15` 与 `2026年3月2日` 混用 |
| 中文句中半角标点 | ⚠ 警告 | `入组后,需完成评估;` 应为全角 |
| 括号不配对 | ⚠ 警告 | `详见附录（A。` |
| 连续空段落 | ⚠ 警告 | 删段后留下的空壳，带列表样式会渲染成空项目符号 |
| 表格空单元格 | ⚠ 警告 | 申报资料中空值一般应写"NA"而非留空 |
| 文档属性 | ◻ 待人工 | 作者/最后修改人可能带出上一版信息，递交前确认是否清除 |

### 文本层（AI 按方法论核查）

- 语义矛盾——**不同措辞表达出互斥要求**（危害最高，字符串比对完全无感）
- 数值依赖链断裂（改了剂量没重算累计暴露量）
- 封闭性措辞名不副实（自称"汇总了全部要求"，实际漏收）
- 条件性条款不可执行（"参照末次给药 24 小时采样"在提前停药场景下时间点落在过去）
- 中文欧化句式 / 英文 Chinglish、时态漂移、情态动词（must/should/may）误用

## CDE / FDA 规则对照

| 项目 | CDE | FDA |
|---|---|---|
| 纸张 | **A4**（21×29.7cm） | US Letter |
| 中文字体 | **宋体**（强制） | 不适用 |
| 西文字体 | **Times New Roman** | Times New Roman **或 Arial** |
| 正文字号 | 中文不小于小四（12pt） | 12pt |
| 表格字号 | 不小于五号（10.5pt） | ≥10pt（9pt 为下限） |
| 行距 | 1.5 倍 | 未强制 |
| 页边距 | 纵向：左2.5 / 上2.0 / 其他1.0 cm<br>横向：上2.5 / 右2.0 / 其他1.0 cm | 四边 ≥1 英寸<br>（硬下限：左0.75in、其他0.375in） |

**中美双报同一品种时两套都要跑。** 最容易出错的两点：
纸张（A4 vs Letter，换语言递交时不会自动改）；
字体（FDA 允许 Arial，CDE 只认 Times New Roman + 宋体）。

规则出处与核对日期见 [`references/cde-format-spec.md`](references/cde-format-spec.md)
与 [`references/fda-format-spec.md`](references/fda-format-spec.md)。

## 常见问题

**Q：报错 "不支持旧版 .doc"**
先在 Word 里另存为 `.docx`。旧版二进制格式没有可解析的样式结构。

**Q：提示缺少 python-docx / pypdf / pymupdf**
```bash
pip3 install python-docx pypdf pymupdf
```

**Q：扫描版 PDF 能查吗？**
只能判断"有没有 OCR 文字层"。OCR 认错字查不出来，仍需人工抽查。

**Q：为什么合规的文档也报"警告"？**
警告是"合规但异常"，比如边距远大于规定值——通常是手工调格式留下的痕迹，
提示你确认是否有意为之，不一定要改。

**Q：CDE 规则里的数值可靠吗？**
出自《药品注册申报资料格式体例与整理规范》（CDE，2020-10-01 施行），
经两处公开转载全文相互印证。**但未直接读取 CDE 官网附件原件**，
正式申报前建议以官网现行有效版本复核一次。

**Q：部门有自己的模板，比 CDE 更严，怎么办？**
在 `scripts/docqc.py` 的 `CDE_SPEC` 旁按同样结构加一个 `DEPT_SPEC`，
注册到 `PROFILES` 字典即可，不需要改检查逻辑。

**Q：能直接帮我改文件吗？**
默认只出问题清单。若要求直接改，**改完必须做全文差异比对**确认"只动了预期位置"——
AI 编辑引入的新错误与原有错误同样常见（批量替换过度命中、删段留空壳、
把内容插进目录而不是正文）。详见 `references/methodology.md` 第四节。

- **不替代人工签字**。凡用于监管申报、方案定稿、安全性判断的内容，

- 本工具**不上传任何文件内容**，全部在本地解析。
